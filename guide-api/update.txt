3. ENDPOINT AKTIF SAAT INI (FINAL)
----------------------------------
Auth (tetap):
  POST   /auth/login
  POST   /auth/register (via users)
  GET    /users, POST /users, GET /users/:id, PATCH /users/:id, DELETE /users/:id

Pegawai:
  GET    /pegawai
  GET    /pegawai/:id
  POST   /pegawai {namaPegawai}
  PATCH  /pegawai/:id
  DELETE /pegawai/:id

Katalog-Model:
  GET    /katalog-model
  GET    /katalog-model/:id
  POST   /katalog-model {namaModel}
  PATCH  /katalog-model/:id
  DELETE /katalog-model/:id

Aktivitas (BARU, ganti aturan-komisi/master-aktivitas):
  GET    /aktivitas                 -> semua (order id desc)
  GET    /aktivitas/aktif           -> hanya statusAktif=true
  GET    /aktivitas/:id             -> detail
  POST   /aktivitas {namaAktivitas, persentase, statusAktif?}
  PATCH  /aktivitas/:id {namaAktivitas?, persentase?, statusAktif?}
  PATCH  /aktivitas/:id/nonaktifkan -> set statusAktif=false (idempotent)
  Semua butuh JWT. Error 409 jika nama duplikat, 404 jika id tidak ada.

Unit-HP:
  POST   /unit-hp {imei5, idModel, kapasitasGb?, warna?, regionGaransi?, batteryHealth?, keteranganKondisi?, statusStok?}
  GET    /unit-hp (include model)
  GET    /unit-hp/:imei5 (include model+campur pembelian/penjualan)
  PATCH  /unit-hp/:imei5 (imei5 tidak bisa ubah)

Pembelian (UPDATED - dinamis):
  Lama: POST {imei5, tanggalMasuk, hargaBeli, idPicSeller, idPicCodBeli}
  Baru: POST /pembelian {imei5, tanggalMasuk, hargaBeli, aktivitas?: [{idAktivitas, idPegawai}]}
        aktivitas dinamis, contoh [{idAktivitas:1, idPegawai:1}] untuk Pencari Barang
        backward compat: masih terima idPicSeller/idPicCodBeli (akan mapping otomatis ke aktivitas jika aktivitas kosong)
        Dalam transaction: create pembelian + aktivitas_pembelian + komisi (nominal = hargaBeli * persentase /100, snapshot persentase)
  GET    /pembelian (include unitHp.model + aktivitas.aktivitas+pegawai + komisi.pegawai+aktivitas)
  GET    /pembelian/:id

Penjualan (UPDATED - dinamis):
  Lama: POST {imei5, tanggalKeluar, hargaJual, profitKotor?, idPicBuyer, idPicCodJual} -> auto 4 komisi fixed enum
  Baru: POST /api/penjualan {imei5, tanggalKeluar, hargaJual, profitKotor?, aktivitas?: [{idAktivitas, idPegawai}]}
        aktivitas dinamis, contoh Pencari Pembeli + COD Jual
        backward compat: idPicBuyer/idPicCodJual masih dipetakan jika aktivitas kosong
        Auto: profit = hargaJual - hargaBeli (jika profitKotor tidak dikirim), buat aktivitas_penjualan + komisi (nominal = profit * persentase /100), update unit status Terjual
  GET    /api/penjualan
  GET    /api/penjualan/:id

Komisi (UPDATED):
  Lama: peranTugas enum, hanya dari penjualan, include picBuyer
  Baru: idAktivitas FK, bisa dari pembelian ATAU penjualan, include aktivitas + pegawai + pembelian/penjualan
  GET    /api/komisi
  GET    /api/komisi/:id
  GET    /api/komisi/summary -> {totalKomisi, totalTransaksi, perPegawai[], perAktivitas[], perPeran(alias)}
  GET    /api/komisi/pegawai/:id -> filter idPegawai
